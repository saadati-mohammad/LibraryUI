# Input and interaction control audit

Scope: all current Angular routes and shared form/control components in `src/app`. The book, member, loan, and reservation forms use reactive forms. A control listed by field name below has one implementation decision for its described use; repeated filter/form fields are checked separately where their validation or meaning differs.

## Public, member, and barcode controls

| Route / file | Control and purpose | Type, default, and validation | Accessibility and behavior | Decision / verification |
| --- | --- | --- | --- | --- |
| `/` and `/catalog` — public home/catalog | Search phrase, subject filter, sort, paging | Native search/text/select-like buttons; query is preserved in the URL; bounded page size | Labeled searchbox, explicit search action, category navigation, empty/error states; mobile navigation opens with a named button | Keep native controls; desktop/mobile public discovery E2E |
| `/register` — registration form | Names, email, national ID, optional phone, password and confirmation | Native text/email/tel/password; required names/email/ID; ID 10 digits; password 12–128 chars; confirmation must match | Associated visible labels, autocomplete/input modes, inline alert, submit disabled until valid | Keep native fields; registration unit and desktop/mobile member E2E; registration disabled by default in production |
| `/account` — member portal | Phone update, loans, reservation actions, logout | Native tel input and buttons; phone length bounded; only active reservations can be cancelled | Member-only route, labeled form/action buttons, status/error states, responsive labeled cards | Keep; H2 ownership and desktop/mobile signup/reservation E2E |
| `/book` add dialog — barcode entry | Focused ISBN/barcode field, metadata lookup, candidate selection | Native text input; whitespace/hyphens normalized; ISBN-10/13 checksums; duplicate scan suppressed per dialog | Focus moves to the field on add; scanner Enter suffix and manual button supported; no global key capture; status uses `aria-live`; manual entry remains available | Keyboard-wedge USB/Bluetooth; no camera; unit tests, provider-mapping tests, desktop/mobile invalid scan/manual fallback E2E |

## Cross-checks

- Search found no time, date-time, date-range, checkbox-group, radio, range, multiselect, chip, or role-selector control. Registration assigns MEMBER server-side; role provisioning remains staff/admin work and has no UI.
- Text filters for books and members debounce and compare consecutive values; loan filters apply explicitly. Reservation/member/book type-ahead uses bounded requests and cancels stale searches.
- Native button semantics replaced two template-download anchors that had `role="button"` and custom key handlers.
- No commented-out executable UI path remains. Old date-tooltip sample code, dead theme CSS, and a stale book filter implementation were removed; remaining comments explain active behavior or API contracts.
- Browser checks cover public, member, and staff workflows, all current routes, dialog behavior, no-violation axe scans, and desktop/mobile overflow. Keyboard-only completion of every form and every file rejection edge still deserves a manual/automated extended pass.
